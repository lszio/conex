## 1. 范围（P1 当前实际可达的库面）

- 公共类型：`conex-proto::cid` 唯一内容寻址函数（`content_cid` + `manifest_tree` + `addressing_for_parts`），`source/read` 与 `blob/*` 同一份实现。
- 持久化存储：`conex-content`（`cap-std` 受限根 + `tmp+rename` 写 + `recover()` 崩溃恢复 + 引用计数 GC）。
- 会话/附件：`conex-core::session`（`SessionStore` + epoch fencing + 120 s 默认租约 + GC）。
- 操作副作用治理：`conex-core::operation`（dedup key + 24 h TTL + crash recovery + GC）。
- Broker 业务处理器：`conex-host::broker`（`blob/*`、`session/*`、`operation/*`、`agent/*` 严格解码 + 输出校验），仅经 `crates/conex-host/tests/p1_e2e.rs` 4 项用例覆盖；宿主进程未挂载。
- OIDC code+PKCE + 一次性 ticket：`conex-host::agent::{OidcRegistry,TicketRegistry}` 库面（开发模式：无 issuer/audience 签名校验；ticket = SHA‑256(自报字段)）。
- Agent 注册表：`conex-host::agent::AgentRegistry` + `conex-agent` CLI 桩（只 echo JSON，不主动反向连接）。

**未实现/未接线（不应视为交付）：**

- WSS `/wss` 业务循环、protobuf WSS profile（`conex-protobuf-wss-v1` 当前 `not_implemented`）。
- P1‑04 Stream（`stream/ack`/`stream/flow`/`stream/reset` 协议 + 慢消费者 + 重放缓存）。
- 真 OIDC（issuer/audience 签名、JWKS、RS256）。
- Blob/session/operation/agent 经 `StaticPolicy` 的资源级授权与审计（design §5/J8）。
- 1 GiB 经 wire 的弱网续传（设计 §14 第 1 项）。

## 2. 启动 P0 主机（不受 P1 影响）

```toml
listen = "127.0.0.1:8787"
allow_loopback_http = true
audience = "host.local"

[[tokens]]
token_hash = "<sha256 of bearer token, hex>"
principal_id = "alice"
tenant_id = "tenant-a"
audience = "host.local"

[[policy]]
principal_id = "alice"
tenant_id = "tenant-a"
endpoint_id = "notes-local"
actions = ["list", "read", "search"]
root = ""
subtree = true

[[endpoints]]
id = "notes-local"
tenant_id = "tenant-a"
provider_id = "source"
kind = "source-fs"
provides = ["source/list", "source/read", "source/search"]
root = "fixtures/p0/notes"
```

启动：

```bash
./scripts/bootstrap-toolchain.sh
source .toolchain/env.sh
cargo run -p conex-host -- examples/p0/host.toml
```

不要把 `content_root`/`session_root`/`operation_root` 写进 `host.toml`——`HostConfig` 显式 `deny_unknown_fields`，目前不接受这些键；接线阶段才会加回。

## 3. 当前可达的 P1 入口（仅测试中）

`crates/conex-host/tests/p1_e2e.rs` 直接构造 `Broker` + 三个 store + `HostSide`，通过 `Broker::invoke` 调用 `blob/*`、`session/*`、`operation/*`、`agent/*`。下列表格描述的是 in-process 行为，不是 wire 行为。

| 方法 | 用途 | 关键约束 |
|---|---|---|
| `blob/put` | 创建/续开 upload | `formatVersion=1`、`declaredSizeBytes`、`declaredChunkSize`、`expectedRootCid`、`access.{providerId,plane,resourceId}`、`requestedLeaseMs?` |
| `blob/chunk` | 提交块 | `uploadId`、`chunkIndex`、`chunkCid`、`chunkBytes` (base64 或 `Vec<u8>`) |
| `blob/commit` | 原子提交 | `uploadId`、`declaredRootCid`、`persistence="local"`；服务端按自身 receipt 重算根并持久化 manifest 对象 |
| `blob/pin`/`unpin` | 引用管理 | `rootCid`/`pinId`、`pinUntilMs?` |
| `blob/have`/`get` | 持久块查询/取回 | `chunkCids` / `chunkCid` |
| `blob/cancel` | 取消上传 | `uploadId` |
| `session/open` | 创建 Session + attachment | `requested.{principalId,tenantId,providerEndpointId,plane}`、`recovery`、`attachmentId`、`peerRole`；`RecoveryLevel::Persistent` 强制降级 `in_process` |
| `session/resume` | 续接 | `sessionId`、`attachmentId`、`expectedEpoch`、`binding` 不匹配 → `unauthorized`；epoch 不匹配 → `resume_unavailable` |
| `session/renew` | 续租 | `sessionId`、`attachmentId`、`expectedEpoch` |
| `session/close` | 关闭 | `sessionId`、`attachmentId` |
| `operation/get` | 取回结果 | `key.{tenantId,principalId,providerEndpointId,spaceId?,resourceId,method,operationId}` —— **当前从请求体读 principal/tenant，无 caller 比对，broker 层不强制跨主体隔离** |
| `operation/cancel` | 取消 | 同上 key；当前会 auto-accept 一条 NonReplayable 记录以让 dedup 可观察 |
| `agent/register` | 反向注册 | `agentId`、`providerIds`、`methods`、`resources`、`hostOrigin`（仅前缀 `conex://`）—— **无 host 真实身份/公钥校验** |
| `agent/heartbeat` | 心跳 | `agentId`；当前心跳记录不驱动租约回收 |
| `agent/resolve` | 查找 | `providerId`、`resourceId`、`method` |

## 4. P1 验收当前状态（设计 §14）

| # | 验收 | 状态 |
|---|---|---|
| 1 | 1 GiB protobuf blob 通道弱网续传 | ✗ 无 WSS protobuf 业务实现；1 GiB 仅 `conex-content` 单测 |
| 2 | 坏块/无假 committed/并发 GC | ◐ 前两项覆盖；并发 GC×commit 竞态未测 |
| 3 | 30 s 断网恢复 / fencing / session_lost | ◐ 仅 store 状态机；无网络层 |
| 4 | ACK/credit/慢消费者/`slow_consumer` | ✗ 无实现 |
| 5 | 伪 host 拒注册 / 日志脱敏 / 跨主体 resume | ✗ hostOrigin 仅前缀校验、ticket 无签名、无调用方比对 |
| 6 | 幂等取回 / `outcome_unknown` 不自动重试 | ◐ store OK；broker 层 `operation/get` key 来自请求体 |
| 7 | inline/ref 往返 / 大内联拒绝 | ◐ 库内 OK；wire 未闭环 |

## 5. 内容寻址

`conex-proto::cid` 是规范实现：

- `len <= chunk_size` → CIDv1 raw/SHA‑256。
- `len > chunk_size` → `ChunkManifest`（protobuf wire，1024 entries/层，>1 层自动分层）。
- 黄金向量由 `conformance/tools/gen_manifest_goldens.py` 用 `protoc --encode`（C++ protobuf）+ Python 标准库独立生成，与 prost / ts‑proto 逐字节一致。
- 修改规范字节要 bump `formatVersion`，重算黄金。

`source/read` 与 `blob/*` 使用同一函数；fs/http-catalog 的 `MAX_DOC_BYTES = 256 KiB`，所以读取路径不会跨 chunk_size，但行为不变。

## 6. 错误码 → 业务策略

`conex_proto::v1::ErrorCode` 在 wire 与 Rust 之间统一：

| Code | 触发 | 业务处理 |
|---|---|---|
| `BadBlob` | commit 重算根失败 / 长度不符 / 块被篡改 | 不要盲重试；重传整段 |
| `ResumeUnavailable` | epoch 不匹配 | 重新 `session/open` |
| `SessionLost` | attachment 租约过期 | 重新 `session/open` |
| `Conflict` | 同 operationId + 不同 param_digest | 修正参数后重新发起 |
| `OutcomeUnknown` | operation 已发送但未确认 | **不自动重试**（design §7.3） |
| `Unauthorized` | binding / ticket / OIDC 校验失败 | 重新建立身份 |

## 8. 已知缺陷

- 跨进程 Session 恢复（host 重启）：不在 P1 范围。
- WSS `/wss`、`/tickets`、`/oidc/*` 已挂入 host，协议与契约一致；hello 广告 P1 profile + 方法。
- OIDC：未配置 `[oidc]` 时是开发模式（code/PKCE 本地签发，无签名校验）；配置 `[oidc]`（issuer pin + client_id + nonce + JWKS）后 `/oidc/token` 校验 RS256 id_token 签名/iss/aud/exp/nonce 才签发 ticket。
- Agent 注册只接受与 `host_origin` 配置一致的 `hostOrigin`（`conex://` 前缀仅作开发默认）；心跳不驱动租约回收。
- P1-04 Stream 已有真实实现与行为向量测试（`crates/conex-core/tests/stream.rs`）。
