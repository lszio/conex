**目标：** 在两个 WSS Profile（JSON 与 protobuf）与 conex-agent 反连之上，交付有界 blob 分块 / 持久提交 / pin / GC、Stream 与网络恢复、浏览器 ticket、Session / operation 状态，以及具备真实原子前提的条件写。

**非目标 / 边界：**

- 不承诺 host 重启或进程退出后的跨进程会话恢复：此类情况返回 `session_lost`。
- 不实现 sync/P2P、目录发现与 ACP/MCP 桥接（属于 P2/P3）。
- 不引入数据库；持久上传与操作状态使用本地持久存储。
- 沿用 P0 的 Cargo workspace 与装配根，不新增空的 `conex-agent/node/coordinator` crate。

## 1. 执行原则

- 沿用 P0 的 data-driven Registry / MethodContract：新 Profile 与新方法只新增注册项和适配器，不在 core 业务路径按 Profile 或 provider 名字分支。
- **先冻结契约与跨语言向量，再实现**；P1-01 是 P1 实现的唯一入口。
- 每个工作包按「具体失败向量 → 最小实现 → 所声明能力的正反向测试 → 范围受控提交」推进。
- 未实现的方法 / Profile 不广告。网络恢复、持久 blob 与条件写能力在对应工作包验收通过前不得出现在 hello 的能力列表。
- 设计已冻结的语义（错误码、信封、平面、身份隔离）不因 P1 实现而改变；需要变更时先改设计/向量。

## 2.1 P1-01b 规范化字节统一（2026-09-16 复核发现；**已完成**）

> 结论（2026-09-16）：规范化字节冻结为 `ChunkManifest` 的 protobuf wire 编码（§3.1/§3.2），唯一实现 `crates/conex-proto/src/cid.rs`；`conex-content` 删除自有实现并在 commit 时按上传自身块重算根；`source/read` 改用同一函数；向量由 `conformance/tools/gen_manifest_goldens.py` 以 `protoc --encode` 独立生成。证据见 [P1 验证记录 § P1-01b](../verification/p1.md)。

**当时的问题：** 同一份内容的 manifest 根 CID 在仓库内由三处不同代码给出，其中两处互相矛盾。

| 位置 | 规范化字节 | 载体 |
|---|---|---|
| `crates/conex-proto/src/cid.rs`（`MANIFEST_PREFIX` + `content_cid`/`manifest_bytes_for_leaves`） | `manifest/v1/`（含斜杠）后接叶子 CID 文本，按 chunkIndex 升序 | `conformance/vectors/p1/chunking.json`、`sdk/typescript/tests/chunking.test.ts`、`scripts/dev/p1-vectors.rs` |
| `crates/conex-content/src/transfer.rs`（`chunk_payload` → `manifest_cid_for`，`decode_content` 内联同规则） | `manifest/v1`（**无斜杠**） | `crates/conex-content/tests/blob.rs:97`、`tests/transfer.rs` |
| `crates/conex-provider-fs/src/read.rs:97`、`crates/conex-provider-http-catalog/src/lib.rs:109` | 整段字节的 `cid_for_raw`（不走分块、无 manifest） | P0 `source/read` 输出 |

独立复算（不依赖本仓库代码；512 KiB 的 `0x01`，256 KiB 分块）：

| 计算方 | 根 CID |
|---|---|
| 冻结向量 / `conex-proto::cid::content_cid` | `bafkreiha7xatdgk3b3vbttawrjbslxdgz5t2e3laqtxhywbdercr4nvkgy` |
| `conex-content::transfer::manifest_cid_for` | `bafkreidr75abqgsjqatzlbel4nvxdew6zbfuqxh65l7mctswgnmqmlii4` |
| `source/read` 的 `cid` | `bafkreibtufilz2ytyguzeiy6mw2pvulicuqs7qdm3naitfwtf3vsz346xm` |

**后果：** 违反设计 §5.3「同一内容不得同时声明两种可比较地址」与 §5.4「同一内容产生同一根」。按冻结向量算根的客户端会被 P1-06/P1-07 的 `declared_root` / `decode_content` 判为 `bad_blob` / `DeclaredRootMismatch`；`blob.json` 不含任何黄金 CID，所以两侧测试全绿也没有暴露该分歧。

**同时暴露的契约缺口：**

- `docs/contracts/p1-chunking.md` §3 冻结的是「protobuf `ChunkManifest` wire 才是规范化字节」，而两套实现与全部向量都用文本前缀；设计 §5.3 明确禁止依赖 protobuf 序列化确定性。契约正文与已冻结向量互相矛盾。
- 设计 §5.4 要求 manifest 条目含「子 CID、逻辑长度及总长度」，契约 §3 也列了 `formatVersion → chunkSize → contentLength → root`；当前扁平文本编码只拼叶子 CID，根不绑定 `chunkSize`/`contentLength`，`> 1 MiB 分层` 规则未实现且 `chunking.json` 无对应用例。
- `crates/conex-proto/tests/chunking.rs`、`tests/p1_contracts.rs`、`sdk/typescript/tests/p1_contracts.test.ts` 只断言向量 JSON 的字段形状，不断言行为；`chunking.json` 的 `rejects` 数组无任何断言；`chunking.rs` 中 `_manifest_cid` 计算后被丢弃，不构成验证。

**已冻结的决定（2026-09-16）：**

| 编号 | 决定 | 结论 |
|---|---|---|
| D1 | manifest 规范化字节的唯一形式 | **protobuf `ChunkManifest` wire**（契约 §3.1/§3.2）。理由：`chunking.proto` 是唯一结构类型源且已冻结 `formatVersion/chunkSize/contentLength/叶子条目`；它的编码规则限定在窄结构（字符串 + uint32 + repeated message），由黄金字节向量在 Rust/TS 两侧逐字节验证，任何序列化行为漂移都会让门禁失败；文本前缀方案需要把已经冻结的类型源改掉。 |
| D2 | 根 CID 是否绑定 `chunkSize`/`contentLength` | **绑定**（`content_length`、`chunk_size`、`format_version` 都在规范化字节里，且叶子数必须等于 `ceil(content_length/chunk_size)`）；`formatVersion` 保持 1，因为结构化格式此前从未发布，无需提升版本号。分层按 `chunking.proto` 的 1024 项/层规则实现。 |

**验收（全部通过，证据见验证记录）：** 唯一函数（`conex-proto/src/cid.rs`）与 TS `sdk/typescript/src/content.ts` 对同一输入给出同一根与同一字节；黄金向量由 `protoc --encode` 独立生成并在两侧逐字节校验；`blob.json` 的多块用例引用 `chunking.json` 的 `two_full_chunks` 并在 `conex-content` 侧消费；`conex-content` 不再有第二套规范化字节，且 commit 从上传自身 receipt 重算根（调用方不能再传叶子列表）；`source/read` 的 `cid` 与 `content_cid` 对齐（含上限边界用例）；`chunking.json` 的 `rejects` 与分层用例有真实断言；`scripts/dev/` 删除。

### 3.5 P1-07 Blob 流与续传

- **新建**：`crates/conex-content/src/transfer/{reader,writer,decoder}.rs`，将 `blob/chunk` 数据帧绑到 P1-04 的 Stream。
- **接口**：客户端拿到 manifest 根 CID 后通过 `blob/have` 询问已持有块；缺块经 Stream 续传；服务端校验 `chunk_cid == cid_for_raw(chunk_bytes)`；inline 阈值沿用 `BlobPut.inlineThresholdBytes`，超出拒绝 inline。
- **失败向量**：坏块 → bad_blob + 仍可续传；末块 `chunk_length` 与声明 `totalBytes` 不一致 → bad_blob。
- **命令**：`cargo test -p conex-content --test transfer`；`conformance/vectors/p1/transfer.json`。
- **退出**：1 GiB 弱网续传，临时盘/内存有界。

### 3.6 P1-08 操作与条件写

- **新建**：`crates/conex-core/src/operation/{store,record,idempotent,conditional}.rs`；持久记录走 gitignored `.state/conex-operation/`（`redb` 或同等本地 kv；不引入 SQL）。
- **接口**：`operation/get|cancel`；MethodContract 必须选择 `ExecutionClass ∈ {read_only,idempotent,deduplicated,non_replayable}`；`source/write`（若实现）可携带 `expectedRevision`，上游不支持就不广告。
- **失败向量**：响应丢失 → deduplicated 取回，non_replayable outcome_unknown 不自动重试；同 key 不同 param_digest → conflict；过期 → 不可静默重放。
- **命令**：`cargo test -p conex-core --test operation`；`conformance/vectors/p1/operation.json` 已在 P1-01 冻结。
- **退出**：M1.4 副作用诚实。

### 3.7 P1-05 反连 agent

- **新建**：`crates/conex-agent/{Cargo.toml,src/{lib,registry,credentials,workspace,heartbeat}.rs}`，独立进程；通过已授权 peer 注册路径接入 host。

- **命令**：`cargo test -p conex-agent`；`conformance/vectors/p1/agent.json`。
- **退出**：M1.5 反连安全。

### 3.8 P1-09 浏览器入口
