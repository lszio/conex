# conex P1 执行计划

> 状态：**待启动**。本文细化到首个工作包 **P1-01 契约冻结**；P1-02–P1-10 的工作包、依赖与验收沿用 [路线图 §4](2026-09-15-conex-roadmap.md)，在 P1-01 退出后按实际冻结的格式拆成可执行任务，不提前编造尚未冻结的 wire/加密实现。
> 上游规范：[设计 v6](../design/2026-09-14-conex-design.md) §5–§7、§14 P1、§16.2。
> 前置：P0 已交付（`e649ded`）；P0 遗留缺口见 [P0 归档计划](archive/2026-09-15-conex-p0.md)。

**目标：** 在两个 WSS Profile（JSON 与 protobuf）与 conex-agent 反连之上，交付有界 blob 分块 / 持久提交 / pin / GC、Stream 与网络恢复、浏览器 ticket、Session / operation 状态，以及具备真实原子前提的条件写。

**非目标 / 边界：**

- 不承诺 host 重启或进程退出后的跨进程会话恢复：此类情况返回 `session_lost`。
- 不实现 sync/P2P、目录发现与 ACP/MCP 桥接（属于 P2/P3）。
- 不引入数据库；持久上传与操作状态使用本地持久存储。
- 沿用 P0 的 Cargo workspace 与装配根，不新增空的 `conex-agent/node/coordinator` crate。

## 1. 执行原则

- 沿用 P0 的 data-driven Registry / MethodContract：新 Profile 与新方法只新增注册项和适配器，不在 core 业务路径按 Profile 或 provider 名字分支。
- **先冻结契约与跨语言向量，再实现**；P1-01 是 P1 实现的唯一入口。
- 每个工作包按「具体失败向量 → 最小实现 → 所声明能力的正反向测试 → 范围受控提交」推进。
- 未实现的方法 / Profile 不广告。网络恢复、持久 blob 与条件写能力在对应工作包验收通过前不得出现在 hello 的能力列表。
- 设计已冻结的语义（错误码、信封、平面、身份隔离）不因 P1 实现而改变；需要变更时先改设计/向量。

## 2. P1-01：P1 契约冻结（可立即执行）

**目标：** 冻结 P1 的 wire、内容、状态与恢复契约，产出可供实现直接使用的检查单与向量骨架。

**产出文件（新建）：**

- `schema/conex/v1/{session,stream,blob,operation}.proto`（结构类型源）
- `conformance/vectors/p1/{chunking,blob,stream,operation}.json`（黄金向量）
- `docs/contracts/p1-chunking.md`、`p1-blob.md`、`p1-stream.md`、`p1-operation.md`（行为规范，分别对齐设计 §5.3–§5.5、§5.5、§6.2、§7.2–§7.3）
- 生成产物更新（Rust/TS/JSON Schema 与 `tools/codegen.lock.json`）

**必须冻结的决定：**

| 主题 | 冻结内容 | 验收 |
|---|---|---|
| 内容分块 | 256 KiB 定长分块 + manifest 树形构造规则；`contentCid` 对多块内容返回 manifest 根 CID | 跨语言黄金字节；同内容同根；与 P0 `source/read` CID 使用同一函数 |
| 规范化字节 | 签名与根 CID 的输入字节规则；禁止用 protobuf 普通序列化当规范化内容 | 已知答案向量覆盖边界与错误输入 |
| blob 状态机 | `blob/put → chunk → commit`、staging 租约、持久 schema、崩溃恢复点 | 每个写入/commit 崩溃点不产生假 committed |
| operation | 去重键、参数摘要、执行类别 → `retry` 推导、默认 24 小时保留、`operation/get` | 执行后响应丢失 / 崩溃 / 同键异参 / 过期用例 |
| stream | 帧逻辑形态、seq/ACK、累计信用计费、有界控制队列、重放窗口 | 乱序/重复/窗口边界；重复 flow 不加信用；慢消费者可取消 |
| 恢复 | `session/resume` 请求/响应、attachment epoch fencing、窗口不足 `stream/reset` | 窗口内恢复与旧连接 fencing；跨进程恢复明确拒绝 |
| ticket | `/tickets` 一次性 ticket 的绑定字段与 30 秒期限 | 原子消费、过期、跨主体/跨角色拒绝 |

**退出标准：**

1. `cargo xtask generate --check` 通过；Rust 与 TS 生成类型、JSON Schema 与 `.proto` 一致。
2. `conformance/vectors/p1/` 黄金向量在 Rust 与 TS 两侧分类一致；分块/manifest 根 CID 与独立实现一致。
3. 四份 `docs/contracts/p1-*.md` 通过评审，明确标注「已冻结 / 占位待定」。
4. 产出 P1-02–P1-10 的可执行任务拆分（文件、接口、失败向量、命令），并更新本计划的第 3 节。

### 3.1 P1-02 WSS 引导（conex-jsonrpc2-wss-v1 + conex-protobuf-wss-v1）

- **新建**：`crates/conex-transport-ws/{Cargo.toml,src/{lib,bootstrap,profile_json,profile_proto,ws_writer}.rs}`，注册 `conex/1` 固定引导格式（UTF-8 JSON-RPC 2.0，每条 JSON 占一个 WS text message，64 KiB 上限）。
- **接口**：`Hello/HelloResponse` 沿用 `control.proto`；新增 `conex/ready` 与一次性协商 ID；服务端写出 ready 后才接受选定编码的首条业务消息。
- **失败向量**：
  - 业务消息早于 ready result（bad_request）。
  - 重复 ready（bad_request）。
  - profileId/plane/capability 不符（unsupported_capability，列出协商支持列表）。
  - 协商超时 10 秒（timeout）。
- **命令**：`cargo xtask conformance --vectors conformance/vectors/p1/wire-wss`；新 test `crates/conex-transport-ws/tests/bootstrap.rs` 与 `sdk/typescript/tests/ws_bootstrap.test.ts`。
- **退出**：WSS Link 只能进入 ready 后再切编码；proto/JSON 两侧同结果。

### 3.2 P1-03 Session / attachment

- **新建**：`crates/conex-core/src/session/`（`store.rs` + `attachment.rs` + `binding.rs`），固定绑定 `principalId/tenantId/providerEndpointId/plane/workspacePeerId?/humanPeerId?`，attachment epoch 单调递增，租约默认 120 秒。
- **接口**：`session/open|resume|renew|close`，按 `session.proto` 严格解码；`session/resume.expected_epoch` fencing。
- **失败向量**：别人拿到 sessionId 不能恢复（unauthorized）；UI 重连不替换 provider 连接；provider 心跳不能延长 consumer 租约；同 sessionId 重复 resume（resume_unavailable）。
- **命令**：`cargo test -p conex-core --test session`；`sdk/typescript/tests/session.test.ts`（mock 服务端）；`conformance/vectors/p1/session.json` 用同一脚本驱动 Rust + TS。
- **退出**：窗口内 30 秒断网恢复同一 Session；窗口外 stream/reset；host 重启返回 session_lost。

### 3.3 P1-04 Stream / ACK / 信用

- **新建**：`crates/conex-core/src/stream/`（`frame.rs`、`ack.rs`、`flow.rs`、`reset.rs`、`replay.rs`）。
- **接口**：每个 attachment 两条独立 `streamId`；`stream/ack.last_received_seq` 连续；`stream/flow.consumed_bytes` 累计；`stream/reset` 标 `resume_handle`。
- **失败向量**：重复 ack 不加信用；旧 flow 忽略；消费计数超发送量失败；零字节数据帧拒绝；control queue 满断 Link。
- **命令**：`cargo test -p conex-core --test stream`；`sdk/typescript/tests/stream.test.ts`；`conformance/vectors/p1/stream.json` 已经在 P1-01 冻结契约，本工作包把分类映射到具体实现。
- **退出**：30 秒断网后窗口内恢复成功；超窗明确 reset；慢消费者 30 秒后 slow_consumer；零 credit 也能取消。

### 3.4 P1-06 Blob 存储

- **新建**：`crates/conex-content/{Cargo.toml,src/{lib,store,staging,commit,gc,receipt}.rs}`，本地持久后端（gitignored `.state/conex-content/`），持久性等级 `local`。
- **接口**：`blob/put|chunk|commit|pin|unpin|have|get|cancel`（见 `blob.proto`）；`PersistenceLevel::LOCAL` 为 P1 broker 默认值；`replicated(n)` 属于 P3-a 范围。
- **失败向量**（每条对应 `conformance/vectors/p1/blob.json`）：
  - chunk 持久前崩溃 → 重传幂等接受；commit 完成。
  - commit 写根引用前崩溃 → 不出现「缺块却 committed」。
  - staging 租约过期未 commit → 块回收，已接收块允许重新打开上传续传。
  - 持久性等级不支持 → unavailable，不降级。
- **命令**：`cargo test -p conex-content`（含崩溃注入 fixture）；`conformance/vectors/p1/blob.json` 扩展运行时断言。
- **退出**：1 GiB 弱网续传（M1.3）；并发 GC 不删有效引用。

### 3.5 P1-07 Blob 流与续传

- **新建**：`crates/conex-content/src/transfer/{reader,writer,decoder}.rs`，将 `blob/chunk` 数据帧绑到 P1-04 的 Stream。
- **接口**：客户端拿到 manifest 根 CID 后通过 `blob/have` 询问已持有块；缺块经 Stream 续传；服务端校验 `chunk_cid == cid_for_raw(chunk_bytes)`；inline 阈值沿用 `BlobPut.inlineThresholdBytes`，超出拒绝 inline。
- **失败向量**：坏块 → bad_blob + 仍可续传；末块 `chunk_length` 与声明 `totalBytes` 不一致 → bad_blob。
- **命令**：`cargo test -p conex-content --test transfer`；`conformance/vectors/p1/transfer.json`。
- **退出**：1 GiB 弱网续传，临时盘/内存有界。

### 3.6 P1-08 操作与条件写

- **新建**：`crates/conex-core/src/operation/{store,record,idempotent,conditional}.rs`；持久记录走 gitignored `.state/conex-operation/`（`redb` 或同等本地 kv；不引入 SQL）。
- **接口**：`operation/get|cancel`；MethodContract 必须选择 `ExecutionClass ∈ {read_only,idempotent,deduplicated,non_replayable}`；`source/write`（若实现）可携带 `expectedRevision`，上游不支持就不广告。
- **失败向量**：响应丢失 → deduplicated 取回，non_replayable outcome_unknown 不自动重试；同 key 不同 param_digest → conflict；过期 → 不可静默重放。
- **命令**：`cargo test -p conex-core --test operation`；`conformance/vectors/p1/operation.json` 已在 P1-01 冻结。
- **退出**：M1.4 副作用诚实。

### 3.7 P1-05 反连 agent

- **新建**：`crates/conex-agent/{Cargo.toml,src/{lib,registry,credentials,workspace,heartbeat}.rs}`，独立进程；通过已授权 peer 注册路径接入 host。
- **接口**：注册 `providerId/method/resourceId` 白名单；本地 `Secret` 不外发；worker 心跳不能延长 consumer 租约；断线按 attachment 租约回收资源。
- **失败向量**：伪 host（伪造公钥）拒绝注册；未授权 provider 注册失败；日志脱敏（不写 token/ticket/参数原文）。
- **命令**：`cargo test -p conex-agent`；`conformance/vectors/p1/agent.json`。
- **退出**：M1.5 反连安全。

### 3.8 P1-09 浏览器入口

- **新建**：`crates/conex-host/src/web_auth/{oidc,session_cookie,tickets,csrf,origin}.rs`；扩展 `conex-host/src/serve.rs` 注册新路由。
- **接口**：`POST /tickets`（30 秒、原子消费、绑定 principal/host/peer_role/capability_caps/sessionId?）；OIDC code+PKCE；state/nonce 校验；CSRF/Origin 校验修改状态的 HTTP 请求；日志脱敏 ticket/token/参数原文。
- **失败向量**：issuer/audience/nonce 错误拒绝；ticket 重复消费拒绝；过期 ticket 拒绝；跨主体 ticket 拒绝；URL 不带长期 token。
- **命令**：`cargo test -p conex-host --test web_auth`；`conformance/vectors/p1/web_auth.json`。
- **退出**：M1.5 浏览器入口安全。

### 3.9 P1-10 联合验收

- **新建**：`xtask/src/p1_verification.rs`，聚合 §14 P1 七项；`docs/verification/p1.md` 记录每个 acceptance 的命令、产物与故障注入证据。
- **新增驱动**：`crates/conex-host/tests/p1_e2e.rs` 启动 host + 内存 agent + 受限 fs + 受限 catalog，按设计 §14 P1 七项逐项断言；`xtask e2e --suite p1`。
- **退出**：M1.6 P1 验收。

## 5. 开放问题（P1-01 必须解决）

- 分块树的具体 JSON / protobuf 编码与层级上限；manifest 何时分层。
- 规范化内容与签名的格式版本、跨语言实现选择。
- 本地持久存储后端（不引入数据库）与崩溃恢复日志的确切边界。
- 重放缓存的进程内实现，以及「网络恢复」与「跨进程恢复」在产品语义上的明确分界。
- WSS 引导中 `ready` 一次性协商 ID 的生成与校验位置。

## 6. P0 遗留缺口的处理

P0 遗留缺口与处理方式：

| P0 缺口 | 处理 |
|---|---|
| 叶证书等值 pin；错误 audience / 过期证书未向量化；header 上限未测 | 并入 P1-02 之前的 TLS 加固任务，补失败向量 |
| SIGTERM 下在途只读调用排空未测 | 并入 P1-03 Session 租约 / 回收测试 |
| `xtask e2e --suite p0-ts` 只跑 fs provider，两个 provider 的 SDK E2E 未合并 | 并入 P1-10 联合验收：扩展 e2e driver 启动 catalog 并断言 GET 计数 |
| 凭据文件属主 uid 未单独校验；env 用例未起独立子进程 | 保持已知缺口，在 P4 keyring/凭据 broker 前按需补齐 |

## 7. 交接

开始执行前先读设计与本计划，然后按 P1-01 的四项退出标准推进；每完成一个工作包更新第 3 节与本文件复选框，并把真实命令与结果写入 `docs/verification/p1.md`。P2 及以后的范围由路线图控制，不在 P1 顺手实现。
