# Conex MVP-P5 私有访问与网络 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` or `subagent-driven-development`；先读[私有运行契约](../contracts/private-runtime.md)。本文件是待执行计划，不是安全验收证据；不自动部署或提交。

**Goal:** 私有认证、节点侧授权、Web/Emacs授权入口、获准直连/转发、direct-only保护与离线撤权。

**Architecture:** 扩展现有Host/节点，保留S1严格信封。JWT使用ring Ed25519，只有中心能签发；grant可在到期前多次使用，WSS ticket单次消费。nodeEpoch/moduleGeneration与中心link generation分离。

**Tech Stack:** 已有Axum/Tokio/ring/secrecy、proto生成链；rusqlite `=0.41.1`（MIT，default-features=false，bundled+backup）。不引入认证SaaS、通用隧道或自制加密算法。

## 2. P5.1：结构与密码边界

- [ ] runtime_access.proto使用package conex；scope定义spaceId/providerEndpointId/contractId/moduleGeneration/methods/states/workspaceIds/conversationIds/purpose，对应proto snake_case。GrantResponse含token、jti、nodeId、nodeEpoch、expiresAtMs（uint64字符串）。AccessContext只存在可信执行环境，不能允许客户端通过payload设置。
- [ ] 撤权分页结构明确`{afterRevision,limit}`→`{items:[{revision,kind,target}],nextRevision,hasMore}`，revision uint64字符串，单页<=128且<=196608bytes；缺口要求全量快照，不能按毫秒timestamp同步。
- [ ] grants.rs公开类型与方法如下；JWT整数时间和Conex uint64 JSON不可混用。ring已有原语，签名密钥严格固定来源，不网络下载任意JWKS。

```text
GrantIssuer::load(kid,issuer,pkcs8_secret_ref,policy) -> Result<GrantIssuer>
GrantIssuer::issue(verified_principal,approved_node_epoch,GrantScope,now,ttl) -> Result<GrantResponse>
GrantVerifier::new(issuer,approved_kid_public_keys,node_id) -> Result<GrantVerifier>
GrantVerifier::verify(token,now) -> Result<VerifiedGrant>
VerifiedGrant = {issuer,audience,principal,tenant,node_epoch,scope,iat,nbf,exp,jti,kid}
```

issue在签发前强制0<ttl<=对应purpose上限（relay300秒/direct3600秒），不能只靠verify拒绝自己已签出的超长期grant。非法ttl直接返回错误，不静默截短改变调用方语义。

核心验签算法（所有失败deny，不尝试另一alg）：

```text
reject token >16384 bytes; split exactly 3 canonical base64url segments
strict JSON parse header/claims (duplicate and unknown forbidden)
require alg=EdDSA,typ=JWT,kid in preinstalled key map
ring::signature::UnparsedPublicKey(ED25519,key).verify(header64+'.'+payload64,signature)
require exact issuer,audience,tenant; safe integer iat<=nbf<=exp
require lifetime <= purpose-specific maximum; nbf<=now+60; now<exp
require nodeEpoch=current node boot epoch; moduleGeneration=target module actual generation
return immutable VerifiedGrant; do not consume jti
```

签发用`ring::signature::Ed25519KeyPair`，私钥只在中心，节点只存公钥。编解码用现有base64 crate URL_SAFE_NO_PAD；UTF-8/规范base64url都严格拒绝畸形。测试用公开固定测试向量/独立签名器交叉验签与篡改负路径，不能只有本实现自签自验往返。

## 3. P5.2：认证与中心数据

- [ ] `PrivateConfig`默认关闭（历史运行不偷偷改变）；P9才切新产品默认。开启时与web_guest互斥，配置加载错误而非留访客后门。私钥引用/公钥允许表/issuer/TTL/地址均在受限配置，示例不含秘密。
- [ ] `PrivateStore`专用DB线程、有界队列64、WAL/FULL/外键、user_version迁移；grant_ledger保存jti/subject/scope/nodeEpoch/expiry，不能保存token/私钥/正文。撤权日志单调revision，事务写日志和策略后才回执。
- [ ] 私有登录引导：`conex-host private-bootstrap --config <owned-config>`（本包新增子命令）通过本机管理员命令生成256bit、5分钟单次引导码；本机终端显示一次，文件/日志不保存明文。`POST /private/session`经HTTPS正文消费引导码、精确Origin，建立私有cookie+CSRF；无cookie不再进入访客注册。引导码非模型API密钥，不能混用现有secret文件。
- [ ] `POST /private/grant`接受两条独立认证路径：cookie+Origin+CSRF；或专用客户端Authorization bearer+role校验。先从认证得到principal，再校验目标/范围子集、purpose/策略/nodeEpoch/moduleGeneration，再签发并记ledger；参数中的principal拒绝。
- [ ] `POST /private/revoke`只授予管理操作者，普通ui凭据不自动有撤权管理权；持久提交后立即撤销中心现有连接/订阅可用范围，同步节点。按jti/principal/kid撤权均定义范围和截止时间。

## 4. P5.3：节点授权与直连

- [ ] P2 Authorizer扩展`VerifiedGrant`输入；握手身份和每次操作授权分开。每路入口要求scope.purpose与实际direct/relay路径精确匹配；方法、Workspace、Conversation、state全部必须在grant和节点本地规则交集中，不能仅检查交集非空。内部Caller只能由验证上下文构造。
- [ ] 节点store追加持久撤销与hub同步水位，先提交再回执/清队列。节点重启生成新nodeRuntimeEpoch但仍保留主体/kid撤销；模块generation持久单调。中心重连只换registrationId，不调用set_node_epoch或重置直接会话。
- [ ] 直连配置默认loopback；非loopback须显式allow_remote_direct+TLS+地址/Origin允许表。中心目录仅列批准地址，客户端不能提交任意目标给中心代理。
- [ ] 每命令、events/read、head update都检查exp/撤权/目标代际；过期结束订阅并拒新请求，不能以一次WSS成功无限续权；已发送执行不因此判停止。

浏览器节点直连的完整流程：

```text
Web已认证中心 -> POST /private/grant (purpose=direct)
Web fetch approved-node HTTPS /private/tickets
  Authorization: Bearer grant; Origin=approved web origin
Node validate grant + exact Origin + allowed target; create opaque 30s single-use ticket
Web new WebSocket(nodeWss,[actualProfile,'conex-ticket.'+ticket])
Node atomically consume ticket, verify Origin/target/profile/grant still valid
Node select actualProfile (never echo secret subprotocol); bind VerifiedGrant
Every subsequent operation/update rechecks authorization
```

CORS仅允许精确Origin、POST及Authorization/Content-Type，拒null/*，不要求第三方cookie。网关/Host日志屏蔽认证子协议；旧URL票据路径在私有模式不接收、不保留别名。native/Emacs可直接Authorization头升级，专用bearer申请grant接口必须覆盖实际客户端。测试浏览器本机HTTPS和允许Origin成功，错误Origin失败；P9再验证实际私网浏览器策略/证书。

## 5. P5.4：路径/来源/撤权

- [ ] Host注册元数据与节点本地批准都保存strategy。`direct-only`对invoke、state/head、events读取、blob/内容同步一致拒绝；不能只拦聊天按钮。策略检查在数据读取/副作用发送之前。
- [ ] 发布派生摘要时计算所有源策略的最严格值；仅管理员独立批准精确sourceRef/fieldSet/destination降密才允许扩大。模块permissions不是授权。节点/中心校验同一批准，实际可信模块按批准构建投影。
- [ ] 两路调用共享固定目标/剩余预算/unknown语义；直连失败不自动发第二次relay。取消始终定位原执行；module/cancel只停止等待不等于agent cancel。
- [ ] 节点ready后按持久afterRevision分页获取授权撤销，逐事务应用后推进水位；断线重读可幂等、revision缺口走全量。同步消息只来自已认证配置中心。原有S1 unknown字段拒绝规则不放宽；新增控制方法单独协商并由proto生成。

## 6. P5.5：真实进程/浏览器套件

在xtask添加`private-network`，临时目录启动真Host/Node/native消费者；用受限测试密钥，不接现网。契约N01–N16逐行都有明确断言，另外必须覆盖：

- 同一grant在同WSS和重连后调用两次成功；同ticket重用失败；连接未断但exp到期后调用/read/head拒绝。
- 中心断开和恢复后nodeEpoch不变，既有有效直连继续；仅中心registrationId换代，旧中心句柄失效。
- 节点实际重启后旧nodeEpoch grant拒绝；本地撤权跨重启保持；同一毫秒两条撤销都被revision同步。
- Web cookie+CSRF与native专用bearer均成功申请grant；错误Origin/CSRF、scope仅部分匹配全部拒绝。
- 篡改alg/kid/aud/scope/signature、跨节点token、client payload伪造AccessContext不执行。
- direct-only的invoke/head/read/blob及未经批准的派生relay拒绝。
- 真实发送边界断线返回unknown，实际后端观察没有第二次副作用发送。
- canary分别用测试正文和测试秘密，扫描中心DB/WAL/备份/日志/dump无命中；ledger可含非秘密jti，不能把它误当泄漏秘密。节点授权正文备份不纳入中心“无正文”误判。
- 浏览器实际WSS子协议票据成功，错误Origin/重放拒绝；非秘密实际profile正确协商，URL无ticket/bearer。

永久回归只保留授权边界、撤权/到期、丢水位、未知发送、策略传播等真实行为，不测配置/字段复制。实际浏览器验证使用browser工具，不以mock浏览器截图顶替。
