**目标：** 交付可嵌入、可独立运行的 broker 只读主干——通过同一个授权执行路径读取、列举、搜索受限 fs 与固定 HTTPS JSON catalog，并提供 TypeScript consumer。

**P0 边界：** Linux 优先；只读取 UTF-8 `.md`/`.org`，单文档 ≤256 KiB，目录/快照 ≤10000 项，单页默认 50/最大 100；query 为 1–256 字符区分大小写字面子串，不做正则或写入；目录外的符号链接、非普通文件、非 UTF-8 路径不列入资源；入站仅管理员预注册静态 bearer；不提供 Session 恢复、blob、sync、OIDC/JWT。

## 冻结的实现决定

- **类型源**：`schema/conex/v1/*.proto` 是唯一结构类型源，派生 Rust（prost/pbjson）、TS（ts-proto）与 JSON Schema；生成产物入库、禁止手改。权威严格解码点是 `MethodContract.prepare`/`validate_output`，JSON Schema 只作文档与 TS 边界输入。
- **ResourceId**：UTF-8 斜杠分段相对名，禁止空段、`.`、`..`、NUL、反斜杠或绝对路径；按路径**段**授权；`root=""` 仅允许出现在 list/search。
- **分页**：provider 侧有界快照缓存，每主体/端点最多 4 个、租约 60 秒；cursor 为随机不可拼装句柄，并绑定 principal/endpoint/root/query。
- **wire**：`conex-jsonrpc2-http-v1`，固定入口 `POST /rpc`；ErrorCode 数值全表冻结、`-32019..-32099` 预留；拒绝 batch、重复/未知字段与非法 ULID。详见 [P0 wire 契约](../../contracts/p0-wire.md)。
- **执行顺序**：route → prepare → tenant/plane → 策略授权 → 审计容量预留 → 全局/每 provider 准入 → 可选 resolver/地址准入/连接 → 握手期策略复核 → 可选凭据 → handler（受剩余 deadline）→ 输出校验 → 审计终态。拒绝路径零业务副作用。
- **依赖边界**：proto 不依赖 core，core 不依赖具体 provider/承载，`conex-host` 是唯一装配根；新增 provider 只增注册/适配器，由 `xtask check-additivity` 验收。

## 遗留缺口（移交 P1）

- **TLS**：叶证书等值 pin 未实现（安装 pin 目前仅作附加信任锚）；过期证书、错误 audience 未单独向量化；header 大小上限未单独测试。
- **入场**：SIGTERM 下在途只读调用的排空未单独测试；未认证连接的全局并发上限与 header 上限沿用 axum/hyper 默认。
- **E2E**：`xtask e2e --suite p0-ts` 目前只启动 fs provider，经 SDK 调用**两个** provider 的端到端断言尚未合并进同一 driver；catalog 的 GET=0 由 Task 10 的 catalog 授权单测覆盖（见 [P0 验证记录](../../verification/p0.md)），而非 SDK E2E。
- **凭据**：未单独校验文件属主 uid（以权限位覆盖组/其他暴露）；env 用例通过注入读取器验证，未起独立子进程。

以上处理方式见 [P1 执行计划 §6](../2026-09-15-conex-p1.md)。
