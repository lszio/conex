# Conex MVP-P4 Codex 适配器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` or `subagent-driven-development`，按任务执行；先读 [Agent 领域契约](../contracts/agent-domain.md) 与 [P0 协议探针](../verification/agent-protocol-probes.md)。本文件是待执行计划，不是交付证据；不自动部署或提交。

**Goal:** 在现有节点二进制内交付 Codex app-server 完整交互适配器：thread/turn/item 协议的真实会话、流式、取消、审批拒绝与外部服务所有权；A06 进入可验收状态。

**Architecture:** 适配器是普通节点模块（`conex.agent/1` 契约），操作名经既有 invoke 路径分派，不新增顶层 JSON-RPC 方法。自有 stdio app-server 子进程与外部认证 WS 服务两种后端形态显式分离；外部服务绝不被适配器 kill。领域状态机以节点 SQLite 为唯一权威；thread↔Conversation、turn↔Execution、item↔Message/工具 part。

**Tech Stack:** 现有 Rust/Tokio/conex-sdk；实现依据是本机 `codex app-server generate-json-schema` 实际导出（P0：0.163.0，stable 318 / experimental 452 文件，SHA-256 已录），不照最新文档盲接实验字段。外部 WS 客户端复用节点发布链既有 WebSocket 依赖栈；如确需新依赖，先在计划内锁定版本与许可再安装。

## 2. P4.1 schema 锁定与协议实现

- [ ] 实施时重跑 `codex --version` 与 `codex app-server generate-json-schema [--experimental] --out <owned temp>`，记录 SHA-256；与 P0 的 0.163.0 不一致时重新核对 thread/turn/item 事件名后编码。
- [ ] `initialize`→`initialized`；`thread/start`（approvalPolicy/sandbox/ephemeral 全部来自批准配置）；`turn/start`、`turn/completed`；`turn/interrupt` 为取消请求。
- [ ] `item/agentMessage/delta`（本版本实际事件名含 `item/` 前缀，旧假定 `agentMessage/delta` 会漏消息）→ 领域 delta；`item/started/completed` 工具活动 → tool part（phase 映射）。
- [ ] 历史：优先分页 `thread/turns/list` + `thread/items/list`（`thread/read includeTurns` 已标 deprecated，不依赖）；空 items 不当历史不存在；不可补读区间 `quality=unknown` + gaps。
- [ ] 严格解码：未知字段/重复键拒绝沿用 wire 规则；本机 schema 之外的字段不接，experimental 字段仅在显式协商后使用。

## 3. P4.2 所有权与外部连接

- [ ] 两种形态显式配置区分：owned stdio app-server 子进程（新增 control_kind，进 P2 所有权清单，崩溃走 reconcile/Quiescent(backend_terminated)）；external 认证 WS（`--ws-auth capability-token --ws-token-sha256`，token 随机、只放 Authorization 头，来自批准 secret 来源）。
- [ ] 外部 server identity 用配置键进入 backend mapping；允许地址默认 loopback + 显式批准表；客户端不可提交任意 server 地址或凭据。
- [ ] 外部服务绝不 kill：适配器关闭/断开只断消费者连接；A06 要求"连接断开或关闭适配器不误杀外部 app-server"成为断言。

## 4. P4.3 领域映射

- [ ] `turn/start` → `admit`/`mark_dispatching`/running；`turn/completed` → 终态（静止判据包含工具/后台活动报告）；`interrupted` 才置 cancelled；先自然完成不改编终态；发送前必须持久化 dispatching。
- [ ] `item/commandExecution/requestApproval` → InteractionRequest(kind=approval)；`decline` 为 P0 实测拒绝路径；turn completed ≠ 命令获准；respond CAS 一次发送。
- [ ] 未知 server request：协议内拒绝或显式 unsupported，不无限等待、不自动批准；消费者断开前未决审批 → 恢复后核对，无法确认仍有效即 invalidated，不重放旧批准（P0 §4.3 冻结处理）；interrupt 回执不充当已取消终态证明。
- [ ] ephemeral thread 只作节点侧标注，不写持久映射、不宣称清理成功（P0 实测 delete 报错）；`thread/delete` 仅限本节点创建的 thread 且清理期核实。

## 5. P4.4 experimental 协商与恢复

- [ ] `parentThreadId`/`ancestorThreadId` 需显式协商 experimentalApi（P0 实测默认返回 requires experimentalApi capability）；未协商 → `listSubagents=false` 或关系标 unknown，不伪造派生关系。
- [ ] resume：完成 turn 后 `thread/read`+`thread/resume` 可恢复（P0 已实测）；活动 delta 无损恢复未证实 → 节点持久流兜底、缺口 gap/resync；重连不假设后端重发全部 delta。
- [ ] capabilities 按本机 schema 与 live 实测声明：steerExecution/userInput/cancelSubagent 等未测一律 false，不为通过检查谎报 true。

## 6. P4.5 live 验收（协议消费者）

- [ ] xtask 新增 `agent-codex-live`：真实模型、隔离临时 cwd/thread、finally 清理自己创建的进程与 thread；owned stdio 与 external WS 两形态分别观察。
- [ ] 场景：创建/继续/历史/流式（delta 帧计数断言）；取消 → interrupted 终态；requestApproval → decline 后 turn 正常完成且命令未获准；消费者断开 server 存活、第二消费者 resume（A06 核心断言）；审批未决断开 → invalidated 不重放。
- [ ] offline schema 解析/帧协议测试与 live 分开报告；模型/授权缺失时记录前提缺失，不用 fixture 冒充 live。

## 7. 迁移与退出

注册、配置、样例调用方变更先枚举引用再动手；`backend_mappings` 由集成所有者与 P3 统一；store 迁移 fail closed 语义不变。完成后更新运行手册与证据页，运行：

```sh
cargo test -p conex-agent -p conex-agent-domain
cargo xtask e2e --suite agent-codex-live
cargo xtask check
```

退出：A06 真实通过——真模型会话、审批拒绝、取消终态准确，且连接断开或关闭适配器不误杀外部 app-server。未获 live 前提时本包保持未完成，不得以离线测试关闭。
