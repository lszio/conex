# S2 插件运行时与组合 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 在 TS 与 Rust SDK 中实现对称的插件生命周期（安装/实例化/启动/停止）、本地依赖注入、显式远程绑定与派生模块再发布，并通过 S2-A01…A08 验收。

**Architecture:** 中心零改动。插件运行时在 SDK 侧进程内：一个接入实例 = 一条 S1 连接；本地依赖是进程内句柄，远程绑定固定到 `ModuleRef`；派生模块复用 S1 发布/订阅边界。行为权威：[S2 契约](../contracts/s2-plugins.md)。

**Tech Stack:** TypeScript/Bun、Rust/Tokio、现有 conex-sdk 与 sdk/typescript、cargo xtask。

## 4. U01：TS 插件运行时

**Steps**
- [ ] `definePlugin({ id, modules: [{ name, contract, provides?…, start(ctx) }] })` 工厂；`Instance.start(config)` 完成：组合期校验（模块名唯一、本地图缺失/成环、远程绑定名齐备）→ 建立连接 → 按偏序 start → publish（S1 语义）。
- [ ] `ModuleContext.deps.local(name)` 返回上游模块 start 返回值（服务句柄）；`deps.remote(name)` 返回绑定 ModuleRef 的消费者（invoke/subscribe/cancel 句柄）。本地调用不经信封。
- [ ] 类型化错误：`missing_dependency`、`circular_dependency`（带环路径）、`duplicate_module`、`start_failed`；全部为本地类型，不进 wire。
- [ ] `stop()`：幂等、并发安全；逆拓扑序 unpublish → 关订阅/消费者 → abort handler → 关连接；`Broken`（断线）走同一清理不重连。
- [ ] 导出面更新 `index.ts`；移除因新实现而重复的样例代码，不留第二套发布路径。

```sh
bun test sdk/typescript/tests/s2_plugin.test.ts
bun run --cwd sdk/typescript typecheck && bun run --cwd sdk/typescript build
```

Expected：S2-A01/A02/A04/A05/A06/A08 在 TS 单测（真实 host fixture）可观察。

## 6. U03：S2 双实例样例

**Steps**
- [ ] examples/s2 插件：`counter` 模块 + `derived-counter` 模块（本地依赖 counter；远程模式下绑定对端 ModuleRef），同一 contract 再发布，revision 自独立。
- [ ] 双实例运行：同进程两个实例（或两进程），实例 A（Rust）与实例 B（TS）互绑；样例输出结构化 read/add/snapshot/update/termination 结果。
- [ ] 环境变量沿用 `CONEX_URL/TOKEN/SPACE/ENDPOINT/PEER_ENDPOINT` 约定；host.toml 静态批准两个 endpoint；README 说明运行法。
- [ ] 真实三进程观察：A01 双实例隔离、A02 本地派生、A03 跨实例绑定、A07 跨语言派生消费。

