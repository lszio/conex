# Conex MVP-P3 OMP 适配器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` or `subagent-driven-development`，按任务执行；先读 [Agent 领域契约](../contracts/agent-domain.md) 与 [P0 协议探针](../verification/agent-protocol-probes.md)。本文件是待执行计划，不是交付证据；不自动部署或提交。

**Goal:** 在现有节点二进制内交付 OMP RPC 完整交互适配器：真实会话创建/继续/历史、流式、执行状态、取消与交互回答，backend 映射真实落库；A05 进入可验收状态，并补齐 P0 未覆盖的工具审批 live 证据。

**Architecture:** 适配器是普通节点模块（`conex.agent/1` 契约），操作名作为模块方法经既有 invoke 路径分派（本地/直连 `node/invoke`、中心 S1 `module/invoke`），不新增顶层 JSON-RPC 方法。一个活动会话一个受控 OMP 子进程；进程身份与崩溃核对复用 P2 所有权机制；领域状态机（admit/dispatching/unknown/终态）以节点 SQLite 为唯一权威，OMP 帧只提供观察。并发会话各自独立进程与 session 目录，互不抢占。

**Tech Stack:** 现有 Rust/Tokio/conex-sdk、serde_json 行帧（OMP RPC 是自定义 JSONL，不是 JSON-RPC2）、P1 `conex-agent-domain` Store 与生成链。OMP 版本以实现时本机安装为准（P0 实测 18.13.2，参考安装包 `packages/coding-agent/src/modes/rpc/{rpc-mode,rpc-types}.ts` 与 `session/agent-session-events.ts`）；不引入新依赖，不内嵌第二套 OMP 客户端库。

## 2. P3.1 进程与帧协议

- [ ] 实施时重读本机 `omp --help` 与安装包 rpc 文档实际版本；与 P0 的 18.13.2 不一致时重新核对事件名/字段并更新证据页，不按记忆编码。
- [ ] owned 子进程：批准二进制 + `--mode rpc-ui`（P0 实测可发 `extension_ui_request.method=select` 的唯一模式）+ 每会话独立 `--session-dir` + `--cwd` 限定批准 Workspace root + 自动发现禁用 flag 集（P0 使用的 `--no-extensions --no-skills --no-rules --no-context-files --no-lsp`，live 时逐个复核）。模型/provider 一律来自机器现有授权与批准配置，客户端 payload 不可传。
- [ ] JSONL 帧解码：物理帧 1 MiB 上限、v2 大帧 chunk 重组至逻辑 64 MiB（适配器自有限额，到限断开会话并写诊断，不照搬无界 spool）；未知帧记录后忽略；子进程输出不整段进节点日志。
- [ ] ready 协议协商（协议 1/2）、请求 id 响应关联（有界 map，超时回收泄漏 id）；`message_start/update/end` → 领域消息事件；`prompt_result` + `sessionSettled=true`/`isStreaming=false` 才作终态静止判据；不拿 `agent_end` 单独判完成。
- [ ] `extension_ui_request`（select/input/confirm）→ 领域 InteractionRequest（kind/effect 按 P0 观察映射）；未知 UI 请求 method 显式拒绝并报告，不默认批准、不无限等待。

## 3. P3.2 会话映射与隔离

- [ ] `backend_mappings` 迁移：映射行仅在首次受控创建/恢复成功后写入；未取得后端 sessionId 不填假映射。节点重启用 `(adapter, backend_instance_key, backend_conversation_id)` 找回会话。
- [ ] 一个活动会话一个受控进程 + 独立 session 目录（节点 data_dir 下 0700 私有目录）；并发会话上限来自适配器配置，超限新会话 unavailable 而非抢占活动会话。
- [ ] 进程身份沿用 `ControlIdentity`/`process_identity`/`known_exited`（新增 control_kind，不改 counter 语义）；崩溃后活跃会话转 unknown 占槽，凭恢复核对或 Quiescent(backend_terminated)（仅自有进程）清槽；外部/非自有进程绝不 kill。
- [ ] 只读自有会话历史；catalogScope=node-managed，不扫描、不编辑机器上其他 OMP 会话或运行中历史文件。

## 4. P3.3 领域操作映射

- [ ] create：P1 幂等创建空会话 → 启动进程 → `open_session` 成功后写 backend mapping；继续 = 既有 conversationId submit + resumed open（sessionId 相同）。
- [ ] submit→执行：`admit`→`mark_dispatching`→单次 prompt 发送→delta→`prompt_result`+settled→`apply_backend` 终态；发送前必须持久化 dispatching；回执丢失走 unknown 核对，不自动重发。
- [ ] cancel：映射 `abort` 请求；`prompt_result=aborted` 且 settled 才置 cancelled；先自然完成不改编终态；不支持/无法定位按契约 §6 返回 unsupported/unavailable。
- [ ] 历史：resumed history → Message（稳定 ordinal）；无法补读区间 `quality=unknown` + gaps，不返回空数组谎称完整；活跃消息只从 snapshot/events 取。
- [ ] 交互回答：respond CAS 一次发送；过期/断线必须落到实际明确拒绝项，无法无歧义拒绝 → abort 并等真实静止/核对；OMP ask timeout 默认选 recommended/首项的 timer 必须在开放审批能力前禁用或置于拒绝安全策略（P0 证据 §3）。
- [ ] 工具审批（P0 未覆盖，本包必测）：OMP 工具 approval 请求映射 kind=approval 并真实走拒绝路径，实测通过后才声明 `approval=true`。
- [ ] 子代理：`subagent_lifecycle started`（parentToolCallId）→ 派生 Execution(parentExecutionId) + Relationship(source=backend)；`get_subagents` 空数组不推翻已观察关系；listSubagents/cancelSubagent 按实测声明能力，不可查询标 unknown/false。

## 5. P3.4 live 验收（协议消费者）

- [ ] xtask 新增 `agent-omp-live`：真实模型（机器现有 bs/DeepSeek-V4-flash 授权）、隔离临时 Workspace/会话目录、finally 清理自己创建的进程与目录；不触碰活跃 TUI。
- [ ] 场景：真模型流式完成（settled）；中途取消 → aborted + settled 终态；select 明确拒绝；工具审批拒绝；并发双会话互不干扰；owned 进程重启后同 sessionId 历史恢复；断言 abort 回执 ≠ 已判终态。
- [ ] 模型/额度前提缺失时：证据页记录缺失项，离线帧协议/映射单测单独报告；不用 fixture 冒充 live，不降低 A05。

## 6. P3.5 TUI 附着调查

- [ ] 独立调查既有 OMP TUI 的附着/只读可行性，结论与限制写证据页；不阻塞 RPC 主路径。端点说明明确区分可控（RPC 会话）、只读（附着观察）、不可附着，不把 TUI 接管宣称成已实现能力。

## 7. 迁移与退出

`ImplementationRegistry`、应用包校验、配置样例的调用方变更先枚举引用再动手；store 迁移保持旧版本号 fail closed 语义不变；共享迁移版本号与 P4 协调。完成后更新运行手册与证据页，运行：

```sh
cargo test -p conex-agent -p conex-agent-domain
cargo xtask e2e --suite agent-omp-live
cargo xtask check
```

退出：A05 真实通过——会话持续、后台任务状态与取消终态准确；abort 回执不冒充终态；工具审批获得 live 证据。未获 live 前提时本包保持未完成，不得以离线测试关闭。
