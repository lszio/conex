# Conex MVP-P1：领域状态与恢复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` or `subagent-driven-development`，按任务完成；未通过 P0 live gate 不实施 Adapter，不提交/推送。

**Goal:** 用真实节点 SQLite 实现会话准入、审批 CAS、持久事件及 Rust/TS 消费边界；不依赖模型或中心数据库保存正文。

**Architecture:** 领域逻辑独立为 conex-agent-domain，结构唯一源为 proto。数据库事务原子更新投影/事件，后端发送与数据库明确分离。用现有 module/invoke 查询事件、S1 完整状态提示 head，不新造第二套 push 路由。

**Tech Stack:** Rust/Tokio/prost/pbjson、rusqlite `=0.41.1`（MIT、default-features=false，features=["bundled","backup"]）、SQLite/WAL、现有 TS/Bun 生成链。P0 已实读 [release metadata](https://crates.io/api/v1/crates/rusqlite/0.41.1) 与 [dependencies](https://crates.io/api/v1/crates/rusqlite/0.41.1/dependencies)：非 WASM 使用 libsqlite3-sys；不引入连接池/ORM。实现时由明确安装授权解决依赖获取，不在本计划编写期间安装。

**状态（2026-10-29）：** 本计划已执行；实际结果、与计划的偏差与未交付项见 [P1 实施记录](../verification/agent-domain-p1.md)。下面的复选框反映已执行项，不是未来承诺；`[x]` 行若带括号说明即为该行的实际边界。

## 2. P1.1：结构与严格边界

- [x] 按领域表为 AgentEndpoint、Workspace、Conversation、Execution、InteractionRequest、Message、Relationship 创建消息；所有操作各有独立 Input/Result 消息，禁止以任意 Value 代替整个协议。仅事件 data 的异构载荷使用 proto oneof，生成到各客户端后做类型分派。
- [x] 所有 ID 字段 string，所有 revision/generation/position/time uint64，partIndex/limit uint32；可选值用 optional，不把 absent 与空字符串混淆。非空/范围/状态词表由领域严格验证器完成。UTF-8 字节长度使用编码后长度。
- [x] `crates/conex-proto/src/agent_domain.rs` 定义 `validate_agent_input(method,&Value)`、`validate_agent_output(method,&Value)`，复用 descriptor-derived Schema 与 wire 的 ULID/decimal 规则。原始信封重复键仍在 wire decoder 拒绝，不在转成 map 后检测。
- [x] 契约方法清单与 Agent 表逐项对应；read_only 为列表/get/history/events，non_replayable 为 create/submit/cancel/respond/steer。不把 module/cancel 解释成执行取消。
- [x] 生成 Rust/TS/JSON Schema；添加向量：未知字段、重复嵌套键、数字 revision、超过 i64 事件位置、非法选择、任意 cwd/backendId、128-byte 幂等键边界、超限 UTF-8 content。

计划中的 proto 关键结构（创建时完整补入所引用记录定义，字段来自专项契约，不自创另一个模型）：

```proto
syntax = "proto3";
package conex;
message AgentEventCursor {
  string stream_id = 1;
  string epoch = 2;
  uint64 after = 3;
}
message AgentSubmitInput {
  string conversation_id = 1;
  string idempotency_key = 2;
  string content = 3;
}
message AgentInteractionRespondInput {
  string interaction_id = 1;
  uint64 expected_revision = 2;
  AgentInteractionDecision decision = 3;
}
message AgentInteractionDecision {
  string kind = 1;
  optional string choice_id = 2;
  repeated string choice_ids = 3;
  optional string text = 4;
}
```

`kind` 的互斥语义由 prepare 拒绝（approval 只能有 choiceId 等），不允许 proto 默认空值绕过检查。方法目录集中一处，Host/P2 节点使用同一契约对象，不修改现有 S1_METHODS 顶层清单。

## 3. P1.2：真实数据库与迁移

- [x] 数据目录 0700、DB/WAL/SHM 0600；连接启用 foreign_keys、WAL、synchronous=FULL、busy_timeout=2000；不可用/迁移失败直接报错，不落回内存“成功”。
- [x] DB 工作在一个专用阻塞工作线程，async 请求通过有界 mpsc（容量 64）和 oneshot 回执；满则 quota_exceeded、不阻塞无限排队。跨进程并发仍依赖 SQLite 事务，不以进程内 mutex 替代约束。
- [x] 初次创建 schema.sql，旧库版本高于程序直接拒绝；低版本执行已定义事务迁移，先用 SQLite backup API 制作受限权限备份，不直接复制打开的 WAL DB。P1 无旧 Agent 领域库，绝不操作历史内容数据库。（P1 只有 v1：user_version=0 且无表才初始化；更高版本直接拒绝；备份/恢复一律走 SQLite backup API）

初始关键 schema（所有外键目标在同库；JSON 字段为生成记录序列化，不是未验证用户对象）：

```sql
PRAGMA foreign_keys=ON;
CREATE TABLE store_identity(node_id TEXT PRIMARY KEY);
CREATE TABLE streams(
 id TEXT PRIMARY KEY, epoch TEXT NOT NULL,
 head INTEGER NOT NULL DEFAULT 0 CHECK(head>=0),
 first_available INTEGER NOT NULL DEFAULT 1 CHECK(first_available>=1),
 event_bytes INTEGER NOT NULL DEFAULT 0 CHECK(event_bytes>=0)
);
CREATE TABLE conversations(
 id TEXT PRIMARY KEY REFERENCES streams(id), endpoint_id TEXT NOT NULL,
 workspace_id TEXT NOT NULL, active_execution_id TEXT,
 revision INTEGER NOT NULL CHECK(revision>=1), projection BLOB NOT NULL
);
CREATE TABLE executions(
 id TEXT PRIMARY KEY, conversation_id TEXT NOT NULL REFERENCES conversations(id),
 parent_execution_id TEXT REFERENCES executions(id), generation INTEGER NOT NULL,
 state TEXT NOT NULL CHECK(state IN
 ('accepted','dispatching','running','unknown','succeeded','failed','cancelled')),
 revision INTEGER NOT NULL CHECK(revision>=1), projection BLOB NOT NULL
);
CREATE UNIQUE INDEX one_top_level_active ON executions(conversation_id)
 WHERE parent_execution_id IS NULL
 AND state IN ('accepted','dispatching','running','unknown');
CREATE TABLE interactions(
 id TEXT PRIMARY KEY, execution_id TEXT NOT NULL REFERENCES executions(id),
 state TEXT NOT NULL CHECK(state IN
 ('pending','responding','resolved','expired','invalidated','unknown')),
 revision INTEGER NOT NULL CHECK(revision>=1),
 expires_at_ms INTEGER NOT NULL, decision_digest TEXT, responder_id TEXT,
 projection BLOB NOT NULL
);
CREATE TABLE messages(
 id TEXT PRIMARY KEY, conversation_id TEXT NOT NULL REFERENCES conversations(id),
 execution_id TEXT NOT NULL REFERENCES executions(id), ordinal INTEGER NOT NULL,
 backend_key TEXT, revision INTEGER NOT NULL CHECK(revision>=1),
 state TEXT NOT NULL CHECK(state IN ('streaming','complete','incomplete')), projection BLOB NOT NULL,
 UNIQUE(conversation_id,ordinal), UNIQUE(conversation_id,backend_key)
);
CREATE TABLE backend_mappings(
 adapter TEXT NOT NULL, backend_instance_key TEXT NOT NULL,
 backend_conversation_id TEXT NOT NULL, conversation_id TEXT NOT NULL REFERENCES conversations(id),
 PRIMARY KEY(adapter,backend_instance_key,backend_conversation_id)
);
CREATE TABLE entities(
 id TEXT PRIMARY KEY, kind TEXT NOT NULL, revision INTEGER NOT NULL, projection BLOB NOT NULL
);
CREATE TABLE dedup(
 principal_id TEXT NOT NULL, endpoint_id TEXT NOT NULL, operation TEXT NOT NULL,
 key TEXT NOT NULL, digest TEXT NOT NULL, object_id TEXT NOT NULL,
 created_at_ms INTEGER NOT NULL, expires_at_ms INTEGER NOT NULL,
 PRIMARY KEY(principal_id,endpoint_id,operation,key)
);
CREATE TABLE events(
 stream_id TEXT NOT NULL REFERENCES streams(id), position INTEGER NOT NULL CHECK(position>0),
 recorded_at_ms INTEGER NOT NULL, encoded BLOB NOT NULL,
 encoded_bytes INTEGER NOT NULL CHECK(encoded_bytes>0),
 PRIMARY KEY(stream_id,position)
);
CREATE INDEX events_age ON events(recorded_at_ms,stream_id,position);
PRAGMA user_version=1;
```

`active_execution_id` 的清槽必须 `WHERE active_execution_id = executionId`，不能在新执行已占槽后用旧回调清空。端点/Workspace 投影放 entities，P6 增加具体查询，不需要图数据库。dedup 的 nodeId 由独立节点库归属隐含，不允许一份 DB 被两个节点共用。

## 4. P1.3：准入、发送边界与终态

公开领域入口（返回生成记录/领域错误，不返回后端进程对象）：

```text
Store::open(path,node_id,limits) -> Result<Store>
Store::restore(backup_path,destination,node_id) -> Result<Store>
Store::create_conversation(authorized_scope,input,now) -> Conversation
Store::admit(authorized_scope,AgentSubmitInput,now) -> Admission
Store::mark_dispatching(execution_id,generation,dispatch_token,now) -> DispatchPermit
Store::apply_backend(execution_id,generation,BackendObservation,now) -> ApplyResult
Store::request_cancel(authorized_scope,execution_id,generation,now) -> CancelTarget
Store::begin_response(authorized_scope,AgentInteractionRespondInput,now) -> ResponsePermit
Store::finish_response(interaction_id,permit,BackendResponseOutcome,now) -> InteractionRequest
Store::recover_unfinished(now) -> Vec<ReconcileTarget>
Store::invalidate_unconfirmed_interaction(interaction_id,generation,reason,now) -> InteractionRequest
Store::snapshot(authorized_scope,conversation_id) -> AgentSnapshot
Store::read_events(authorized_scope,cursor,limit) -> AgentEventPage
Store::read_message(authorized_scope,message_id,part_index,offset_bytes,max_bytes) -> AgentMessageChunk
Store::prune(now) -> PruneResult
```

Admission 区分 `Created{execution,dispatch_token}` 与 `Existing{execution}`；Existing 永远不能拿到可发送 permit。dispatch_token 是本进程新准入产生、不可克隆的内部所有权凭证，不上 wire、不从数据库恢复；mark_dispatching 同时以数据库 accepted→dispatching CAS 防止跨连接重复发送。BackendObservation 是领域枚举（Started、MessageStarted、TextAppended、MessageCompleted、InteractionOpened、Quiescent、OutcomeUnknown），适配器负责依据真实协议产生；不是直接把任意后台 JSON 写数据库。

- [x] 先写消费者可见的数据库并发回归，再实现事务。关键 admit 算法如下，错误路径 rollback；任何分支不能漏记幂等或释放别人的槽：
- [x] create_conversation 也在同一事务查写 dedup（operation=create，摘要覆盖endpoint/workspace/title），同键返回同一会话，不重复分配；backend_mappings 只在真实后端确认会话 ID 后写入。测试并发同键 create。（并发同键 create 已有回归；backend_mappings 的写入留给适配器，P1 不登记假映射）
- [x] Store初建持久store_identity(node_id PRIMARY KEY)，open时必须精确匹配。restore只写新的目标目录、先校验备份完整性/同nodeId、为每个stream换新epoch并记录gap；不能用普通open偷偷恢复。拒绝把旧库当另一个node打开。恢复后的既存dedup仍属于原node，明确备份之后丢失的记录无法提供去重承诺，客户端不得自动重试。添加restore→旧cursor resync、错nodeId拒绝、同nodeId旧幂等键查回原对象的回归。

```text
authorize input and workspace
BEGIN IMMEDIATE
delete matching dedup row if expires_at_ms <= now (expired key is a new operation)
find dedup by authenticated principal, endpoint, operation, key
  found + digest differs: ROLLBACK; idempotency_mismatch
  found + digest same: read object; COMMIT; Existing
check unexpired dedup capacity; full: ROLLBACK; quota_exceeded
read conversation + endpoint generation
if active_execution_id != NULL: ROLLBACK; conversation_busy
insert execution(state=accepted,parent=NULL,revision=1)
update conversation set active_execution_id=new_id,revision=revision+1
insert dedup with expiry now+7days
insert user Message(state=complete,role=user) and text in same transaction
append execution.updated + conversation.updated + message.created(empty text window)
append <=4096-byte UTF-8 message.delta chunks for submitted content + message.completed
store submission-to-user-message mapping; backend echo attaches actual backend key to this message
COMMIT
return Created
```

- [x] mark_dispatching 只允许同 generation、同 dispatch_token 且 accepted→dispatching 的一次 CAS；提交后 permit 在内存仅消费一次，P2 Adapter 才能发送。不在 P1 实现假后端。
- [x] apply_backend 校验目标 generation 与全部硬配额：活动执行<=16、未确定交互<=16、活跃消息<=32，以及恢复契约的单记录编码上限。超限在有界事务写gap、执行unknown、端点隔离，不追加无法快照的原始对象；不能自动批准。terminal 由 Quiescent(state,reason) 明确触发（包含取消确认和拥有原实例的确认退出）；一次清槽/失效交互，late cancel不改终态。
- [x] recover_unfinished 将旧 accepted 按“dispatching必须先提交才能发送”的不变量标 failed/not_dispatched、清其槽；旧dispatching/running/unknown保持unknown并占槽，返回只读ReconcileTarget，不返回DispatchPermit。responding交互unknown；pending待核对。不凭PID数字断言旧进程身份，不把旧执行命令送到新代际。
- [x] 恢复核对无法确认pending审批仍有效时，用invalidate_unconfirmed_interaction事务将其invalidated、增加revision、写interaction.updated；执行仍按后端事实保持unknown/占槽，不自动拒绝已发送执行或重放批准。回归包括后端存活但不返回旧审批的情况。

## 5. P1.4：审批 CAS

- [x] begin_response 在 BEGIN IMMEDIATE 内校验授权、有效期、执行/代际、choice、revision；CAS pending→responding，写 responder/digest/event，再提交返回一次性 permit。
- [x] 同一成功答案的重试返回已解决投影；不同答案/主体冲突，unknown 不作为成功查回。不要只用 expectedRevision 决定是否重复，须比对原 decision 摘要/主体。
- [x] finish_response 只接受 permit 对应响应：后端确认→resolved；发送结果不明→unknown；明确不再有效→invalidated。过期需真实拒绝/核对，不默认允许。

关键 SQL CAS（前置所有验证在同一事务，行数必须正好 1）：

```sql
UPDATE interactions SET state='responding',revision=revision+1,
 decision_digest=?1,responder_id=?2,projection=?3
WHERE id=?4 AND state='pending' AND revision=?5 AND expires_at_ms>?6;
```

多端竞答回归使用两个独立 SQLite 连接及线程屏障，不靠 sleep 排序；最终只一个 permit，拒绝方没有副作用请求。外部发送计数不是唯一判据，还要查询落库 winner、revision 与单次事件。

## 6. P1.5：事件/快照/保留

- [x] append_events 编码后逐事件 <=8192 bytes，文本拆分保持 UTF-8 边界和 offsetBytes；分配 head+1..head+n 与投影在同一事务。超限事务整体拒绝，不产生跳号。
- [x] snapshot 从同一事务版本读取 projections/head/min；保留完整活动集合，最近终态/历史/关系按预算减少，关系返回relationshipsHasMore。按16×1024+16×4096+32×2048+2048=149504 bytes预算保证关键元数据可编码，正文窗口可空；不能截断审批含义。添加最大关键集合与大量关系/长回复后snapshot仍可恢复的回归。（P1 关系无数据源：relationships 为空且 relationshipsHasMore=false；活动集合完整、终态按预算裁剪与长回复补读已由回归证明）
- [x] message.created 不内嵌整条正文；投影保存文本，snapshot/history 只返回带 offsetBytes/totalBytes 的窗口。read_message 按授权会话与 UTF-8 边界分页，保证旧字节不可重写；即使一条回复超过帧上限也能 snapshot 后补读，不把分页当 incomplete。
- [x] read_events 检查 epoch、min-1<=after<=head；页最多32事件、结果<=196608 bytes。prune 删连续前缀并更新 min/byte count；读写隔离保证旧读事务一致，不 pin 无限日志。
- [x] 用参数化 now 测试24h边界与按字节前缀清理；测试 after=min-1 正常、min-2 resync、head+1 bad_request、旧 epoch resync。读取重启后的相同 epoch 连续事件，不按 registrationId 去重。

## 7. P1.6：TS 客户端与真实 smoke

`AgentClient` 包装现有能力消费者 invoke，所有公共操作取生成类型。`EventFollower` 接受 `{snapshot,read,watchHead}` 领域传输接口（由真实 SDK 实现，不引入第二层 service locator），状态机：

```text
snapshot -> replaceProjectionAndCursor
watchHead -> start (new registration explicit)
read from cursor -> validate stream/epoch/next position -> apply -> advance
hasMore or latestHead>cursor -> read again (one in flight)
transport lost -> stale -> reauthenticate/rediscover/watch/read
resume_unavailable -> fresh snapshot (never replay commands)
forbidden -> stop, clear pending reads, report revoked
```

- [x] reducer 在同一应用步骤更新投影与 cursor，重复页去重；同键异内容/offset缺口停止并要求重同步。没有完整快照不能把界面质量置 current。
- [x] 真实 Rust recovery_smoke 用临时 DB 创建端点/Workspace/会话、提交执行并 mark_dispatching、写 MessageStarted 与两条 TextAppended 领域观察、close/reopen、recover unknown，再输出 snapshot/page 为 NDJSON。另建只停留 accepted 的会话证明恢复为 failed/not_dispatched 且释放槽。只输出合成 smoke 文本与 IDs，不启动模型，不伪装 Adapter。
- [x] TS example 读取上述真实 NDJSON，运行同一 EventFollower reducer，断言文本只追加一次、unknown 占槽、epoch/position连续；重复读取相同页不得重复文本。失败抛错非零，不返回 mock success。

## 8. 回归与退出

| 用户可见风险 | 永久回归 | 实际证明 |
|---|---|---|
| 双提交/幂等键不同内容 | admission.rs 双连接屏障、同键与不同摘要 | 仅一个槽/permit；同键同执行 |
| 崩溃后重发或幽灵占槽 | recovery.rs 分别重开 accepted/dispatching DB | accepted 确认未发送则失败清槽；dispatching unknown 占槽，两者无 DispatchPermit |
| 双端审批/过期/跨执行 | interactions.rs CAS与范围 | 一次 winner；拒绝无第二副作用 |
| 自然完成与取消竞态 | admission.rs 同事务终态 | 一个终态、旧回调不清新槽 |
