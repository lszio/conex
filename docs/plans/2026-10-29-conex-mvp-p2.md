## 2. P2.1：应用包与实现环境

- [x] application.rs严格实现private-runtime §2的schema=conex.application/1；未知/重复键拒绝。AppPackage字段schema/app_id/version/owner_node_ref/modules/remote_bindings；ModuleSpec字段id/implementation/config_ref/permissions/local_dependencies/exports。RemoteBinding字段name/node_ref/provider_endpoint_ref/contract_id；export字段contract_id/strategy。
- [x] 节点配置提供静态`ImplementationRegistry`：key→实际工厂、已实现契约成员、配置类型与授权上限。config_ref只引用节点批准表；不接受包传任意env/file/command/URL。不能靠名字在节点动态下载代码。
- [x] validate返回`ResolvedApplication{ordered_modules,remote_bindings,exports}`，不只返回()后再用另一套排序。所有标识/上限/授权/来源约束在创建进程之前验证。

关键算法：

```text
check schema, package bytes<=256KiB, owner_node_ref matches trusted installation node
reject duplicate module IDs, binding names, local dependency names
check modules<=64, bindings<=64, deps/module<=64
for each module:
  resolve approved implementation factory and approved config_ref
  requested permissions subset node installation policy
  exported contracts/members actually implemented
  apply source strategy intersection; no self-declared declassification
build indegree/edges from local_dependencies only
stable Kahn order (module name tie-breaker)
if unresolved nodes: report concrete cycle; no side effect yet
remote bindings validate shape/approval, never enter cross-machine start transaction
return one immutable resolved application
```

对应AppError明确InvalidPackage/UnknownImplementation/ConfigRefNotAllowed/DuplicateModule/DuplicateBinding/MissingDependency/CircularDependency/GrantNotAllowed/ExportNotImplemented/ExportNotAllowed/OwnerMismatch，I/O/解析错误含非秘密文件诊断。不能用未定义的impl元数据或包自报exports冒充实际实现。

## 3. P2.2：持久身份、所有权与状态机

Store增加：`begin_node_boot(nodeId)->nodeRuntimeEpoch`、`next_module_generation(moduleKey)->u64`、`record_owned_resource(instance,controlIdentity)`、`list_unreconciled_resources()`、`record_resource_reconciled(...)`。初次创建元数据绑定nodeId，其他nodeId打开同库拒绝。generation在事务内单调，不能靠进程内计数“重启+1”。nodeRuntimeEpoch只在节点进程启动改变，中心link ready不改变它。

迁移表的关键字段：

```sql
CREATE TABLE node_metadata(node_id TEXT PRIMARY KEY, runtime_epoch TEXT NOT NULL);
CREATE TABLE module_generations(module_key TEXT PRIMARY KEY, generation INTEGER NOT NULL CHECK(generation>0));
CREATE TABLE owned_resources(
 id TEXT PRIMARY KEY, module_key TEXT NOT NULL, generation INTEGER NOT NULL,
 owner_epoch TEXT NOT NULL, control_kind TEXT NOT NULL, control_identity BLOB NOT NULL,
 state TEXT NOT NULL CHECK(state IN ('created','active','unknown','released'))
);
```

- [x] 新库创建遵循P1版本，老库备份后追加原子迁移，不覆盖P1 schema或重置user_version。控制身份仅节点受限存储，不投影中心。
- [x] Node内部由一个串行协调任务处理start/stop/reconcile，NodeHandle用有界channel64；同instance并发start/stop不交错创建第二进程。stop幂等，多等待者收到相同最终结果。
- [x] 本地InstanceState=Installed/Starting/Active/Stopping/Stopped/Failed；PublicationState=Unpublished/Registering/Published/Disconnected/Revoked；LinkState独立。配置是定义，NodeHandle/InstanceHandle是求值结果，依赖引用不是资源所有权。
- [x] 自有资源清单登记真实创建者与可验证控制身份；external只有连接引用。节点崩溃后先核对旧资源，未知仍占其运行约束，不能自动启动冲突新实例；进程退出不会自动证明其子进程已退出。核对不能仅凭PID数字，不误杀其他进程。当前实际验证external counter，不冒充尚未安装的app-server Adapter。

实际接口：`Node::boot(config,store,prepared_applications)`安装已解析定义与显式工厂环境；`NodeHandle::start_package(appId)`、`stop_instance(id,duration)`、`stop_all(duration)`、`snapshot()`经有界串行协调器求值。内部核对在boot先执行；LocalApi返回报告/非秘密snapshot，不建立第二套S1 wire协议。`record_resource_ready`补齐spawn前保留项到实际控制身份的owner-epoch CAS；不引入全局service locator。

## 4. P2.3：启动、停止、发布解耦

```text
start_package:
  validate complete graph before network/process side effects
  allocate persistent module generation and owned local scope
  for module in resolved local order: create factory instance; start; record ownership
  on failure: stop created modules in reverse order; persist unreconciled failures
  Active -> expose local capabilities
  independently ask Publication to publish allowed exports (hub may be absent)

on_hub_disconnected:
  mark publication Disconnected; end only this link's subscriptions/pending forwarding
  leave local modules/processes, nodeEpoch, generations, direct sessions untouched

on_hub_ready:
  publish existing local instances -> fresh registrationId
  no replay of pending mutations; old remote refs fail explicitly

stop_instance:
  set Stopping, reject new local resource/command admission
  revoke publication if reachable; fence local routing even when hub absent
  reverse local topology: cancel owned tasks/subscriptions, await bounded cleanup
  stop owned backend through adapter; deadline then terminate only verified owned resources
  disconnect external references without terminating external process
  persist released/unknown resources and emit diagnostics; Stopped or Failed report
```

30秒默认stop deadline，调用方可缩短不能延长已生效总截止时间。失败回滚不吞原错误，清理不完整明确报告并留核对记录；Drop只能同步兜底，不能冒充异步完成。

## 5. P2.4：SDK迁移与LocalApi

- [x] 双SDK Instance保留现有plugin工厂/依赖DI/派生模块，去掉link close→broken→销毁业务的默认联动。业务状态和publication状态分别可查；显式stop才关闭自有业务。不新建AutonomousInstance与旧Instance长期并行。
- [x] instance start在中心不可达时仍能启动无远程必需运行依赖的本地模块；远程依赖使用显式ModuleRef，换代时拒绝/降级，不透明重绑。模块本地invoke走同一领域授权，不把DI类型当沙箱。
- [x] access.rs定义`authorize(trusted_caller,target,method,resource,now)->AuthorizedScope`；P2只接受来自受限本地操作者身份的调用，P5扩展VerifiedGrant。即使监听loopback也不能根据请求体principal认为已认证；本地入口使用受限Unix socket及OS peer UID，不开匿名接口。
- [x] local_api.rs安装实际已实现领域/运行能力，转发到P1 Store与已启动模块；S1严格边界复用，不接受任意进程命令。不实现只返回ok的Agent handler；Agent后端能力未装时返回明确unsupported。
- [x] publication.rs持有已启动本地能力的可撤销发布引用，与Node所有权分离。同Node共享一条中心连接；旧handler/订阅回调含围栏，迟到清理不删新发布。

执行时枚举并迁移Rust/TS所有Instance构造点、S2样例、错误/状态消费者与断连行为测试；S1旧注册句柄失效保持不变。同步s2-plugins契约状态机和运行手册，移除旧broken销毁默认断言而非同时保留两套语义。

## 6. P2.5：回归与实际smoke

永久回归：缺失/循环/重复依赖在进程创建前拒绝；config_ref越权拒绝；中途失败只逆序回收已创建资源；并发stop幂等；断中心不停止本地；重连不重建业务；旧句柄拒绝；nodeEpoch只在boot改变；本地generation跨重启单调；未知旧资源不误杀/不冲突重启。

真进程private-runtime套件必须启动临时Host、Node、一个真实长运行受控模块及一个独立外部进程：

1. 通过真实模块读取运行计数/进程身份。
2. 真停中心，观察本地模块继续增长、本地授权消费继续；不是只断一个mock transport。
3. 重启中心，模块身份/generation/nodeEpoch不变，registrationId新值；旧远程引用失败。
4. 停组合，只有归组合所有的模块停止；另一组合与外部进程仍响应。
5. 再停止Node，确认仅自有进程回收；最后由测试创建者回收外部进程。
6. 在独立场景异常终止节点，重开Store并核对所有权记录；不能因为丢失Child句柄把未知资源判已退出。

测试模块须有真实可观察行为（如模块提供单调计数及受控资源），不是注册空handler；不提前用假Agent宣称OMP/Codex支持。P3/P4再验证真实后端。
