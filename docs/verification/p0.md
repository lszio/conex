## Task 06 — 统一执行、审计、限额与部分结果

| 项 | 命令 | 结果 |
|---|---|---|
| execution | `cargo test -p conex-core --test execution` | 9 passed |
| aggregate | `cargo test -p conex-core --test aggregate` | 2 passed |
| conex-core 全量 | `cargo test -p conex-core` | 36 passed / 0 failed |

- `Host::invoke` 单一执行路径：route → prepare → tenant/plane → policy grant → 审计容量预留 → 全局+每 provider 准入 → 可选 resolver/TargetPolicy/Connector → 握手期间策略版本复核 → 可选凭据 → handler（受剩余 deadline 约束）→ 输出校验 → 审计终态。
- 拒绝路径零业务副作用：denied 调用 connect/resolve/execute 计数均为 0，审计最后一项 outcome=deny。
- 事件序列断言为 `authorize,connect,peer_verified,authorize,resolve,execute,audit_finish`；连接失败或握手期撤销策略时 resolve/execute=0；无 target/credential 的本地路由不触碰远端端口；审计预留失败在 execute 前拒绝。
- 限额：全局 32、每 provider 4/排队 32 请求/8 MiB，RAII guard，排队消耗剩余 deadline，超限 quota_exceeded 或 timeout。
- `invoke_many` 逐目标独立调用、不重置总 deadline；暂停时钟下验证一个成功一个 timeout，空目标返回成功空列表。

## Task 07 — 受限 fs provider 与共享 source 契约

- `conex-source` 提供 `source/list|read|search` 的共享 MethodContract：严格解码（拒绝未知字段/越界 limit/超长 query）、claim 提取（read 精确、list/search 子树）、输出结构校验。

- 说明：symlink 检查按组件用 `symlink_metadata` 拒绝后再以能力句柄打开，覆盖静态 symlink 逃逸；未声称对同一路径的并发替换具备原子免竞态保证（cap-std 能力句柄仍是最终打开点）。

## Task 08 — TLS/HTTP 承载（先验证对端）

| 项 | 命令 | 结果 |
|---|---|---|
| tls | `cargo test -p conex-transport-http --test tls` | 1 passed |
| addresses | `cargo test -p conex-transport-http --test addresses` | 2 passed |
| body_limit | `cargo test -p conex-transport-http --test body_limit` | 3 passed |

- `HttpConnector` 按 `AllowedTarget.pinned_address` 直连（不做 DNS、无连接池、无系统代理），TLS 用 rustls(ring) + 目标 SNI；证书/主机名/信任验证失败映射为 `peer_untrusted`，且服务端未收到任何 HTTP 请求。
- `HttpConnection` 拒绝绝对 URL 与超出安装 `fixedPath` 的路径；3xx 返回 `unavailable` 且不跟随；响应体逐块累计上限（chunked/无 Content-Length 同样受限），超限 `payload_too_large`；请求与响应都受剩余 deadline 约束。
- `TokioResolver` 用同一 deadline 做 DNS，不把 hostname 交给下层再次自由解析。
- 已知缺口（后续补齐）：安装 pin 目前作为附加信任锚，尚未实现叶证书等值 pin；过期证书/错误 audience 未单独向量化；header 大小上限未单独测试。

## Task 09 — env/file 凭据与租户/受众隔离

| 项 | 命令 | 结果 |
|---|---|---|
| credentials | `cargo test -p conex-host --test credentials` | 12 passed / 0 failed |

- `EnvFileStore` 构造只校验引用唯一性与绝对路径，不预读；`resolve` 先按完整 `CredentialKey`（tenant/holder/provider/audience/name/optional principal）精确命中，再比较 `key.audience == peer.audience`，全部通过才进入 `SecretReader`。
- 未命中的 key、跨租户同名 key、principal 不匹配、audience 不匹配都在读取前返回 `forbidden`，测试用可注入读取器计数的读取次数为 0。
- 秘密校验：空值/含 CR-LF/超过 16 KiB 明确报错；不做 trim；`Secret` Debug 恒脱敏。
- 生产 `SystemSecretReader` 拒绝符号链接与非普通文件，Unix 下要求文件非组/其他可读；文件后端路径只来自安装配置，调用方无法提供路径。
- 已知缺口：未单独校验文件属主 uid（当前以权限位覆盖组/其他暴露）；env 用例通过注入读取器验证，未启动独立子进程。
- 解析时机与无缓存由 Task 06 execution 测试（拒绝/TLS 失败 resolve=0，成功时先 peer_verified 后 resolve）与本次 "文件修改后重新读取" 覆盖。
