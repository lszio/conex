- `IdentityMap` 以完整带来源的 `IdentityKey` 精确映射；不同 issuer 的同名 sub 映射到不同 Principal，未知主体返回 unauthorized，不产生默认用户。

## Task 06 — 统一执行、审计、限额与部分结果

| 项 | 命令 | 结果 |
|---|---|---|
| execution | `cargo test -p conex-core --test execution` | 9 passed |
| aggregate | `cargo test -p conex-core --test aggregate` | 2 passed |
| conex-core 全量 | `cargo test -p conex-core` | 36 passed / 0 failed |

- `Host::invoke` 单一执行路径：route → prepare → tenant/plane → policy grant → 审计容量预留 → 全局+每 provider 准入 → 可选 resolver/TargetPolicy/Connector → 握手期间策略版本复核 → 可选凭据 → handler（受剩余 deadline 约束）→ 输出校验 → 审计终态。
- 拒绝路径零业务副作用：denied 调用 connect/resolve/execute 计数均为 0，审计最后一项 outcome=deny。
- 事件序列断言为 `authorize,connect,peer_verified,authorize,resolve,execute,audit_finish`；连接失败或握手期撤销策略时 resolve/execute=0；无 target/credential 的本地路由不触碰远端端口；审计预留失败在 execute 前拒绝。
- 限额：全局 32、每 provider 4/排队 32 请求/8 MiB，RAII guard，排队消耗剩余 deadline，超限 quota_exceeded 或 timeout。
- `invoke_many` 逐目标独立调用、不重置总 deadline；暂停时钟下验证一个成功一个 timeout，空目标返回成功空列表。
